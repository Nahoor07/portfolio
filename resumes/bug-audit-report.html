Scope & approach

  1. Audit: ran the app, website and API locally, reproduced each reported issue on Android, iOS and web, and traced it through logs, network calls and API responses.
  2. Prioritize: ranked bugs by user impact. Crashes, duplicate payments and data leaks come first, then broken flows, then polish.
  3. Fix the root cause: each fix targets why the bug happens, not just the symptom, and comes with a short explanation.
  4. Retest: regression-tested the related flows on every affected platform, and added automated tests where the logic is easy to break again.

Bug details

BUG-01App crashes when opening a store's category screenCritical
PlatformMobile app (React Native: Android & iOS)
StepsOpen any store, then tap a category. The screen crashes as soon as data finishes loading.
Root causeThe loading/error return ran before six useCallback hooks, so the number of hooks changed between renders and React threw "Rendered more hooks than during the previous render".
FixMoved every hook above the early returns. The spinner now shows only when nothing is cached, so the screen also opens faster on repeat visits.
StatusFixed · retested on Android and iOS
BUG-02Duplicate orders and top-ups on slow networksCritical
PlatformMobile app (React Native) + API
StepsOn a slow connection, tap Place Order (or tap it twice quickly). Two orders are created and the card can be charged twice.
Root causeA global setting retried every failed request, including writes. A timed-out order request may already have succeeded on the server, so the retry created a second order. The button also accepted a second tap while the first request was still running.
FixTurned off automatic retries for writes (orders, wallet top-ups, card calls) and locked the Place Order button until the request finishes.
StatusFixed · retested checkout, top-up and saved-card flows
BUG-03"Session expired" dialog reopens in a loop on the websiteHigh
PlatformWebsite (React / Next.js)
StepsLet a session expire on any page, then close the "Session expired" dialog. It reopens about every 30 seconds.
Root causeEvery 401 response re-ran logout and reopened the dialog. A background poll for the unread-notification count kept getting 401s, so the loop never stopped.
FixSession expiry is now handled once until the next login, and the unread-count poll stops after a 401.
StatusFixed · retested login, expiry and re-login
BUG-04Support chat silently stops receiving messagesHigh
PlatformAPI (Node.js, GraphQL subscriptions over WebSocket)
StepsOpen a support chat and leave it idle for a few minutes. New replies stop arriving until the app is restarted.
Root causeThe server never sent keep-alive pings, so proxies dropped idle sockets and clients didn't notice the connection had died.
FixServer now sends a keep-alive every 10 s (configurable), and clients reconnect automatically if none arrives within 30 s.
StatusFixed · retested idle chats on mobile and admin
BUG-05Order payment breakdown doesn't add up to the totalHigh
PlatformAPI (NestJS) → admin and store dashboards
StepsOpen an order with a packing charge in the admin panel. Subtotal + fees ≠ total.
Root causeThe payment-info endpoint never returned packing charges, and the store view calculated amounts from a different source than the super-admin view.
FixReturned packingCharges in the API response and made both views use the order's saved subtotal and discount.
StatusFixed · unit tests added for the payment breakdown
BUG-06Chat input hidden behind the keyboard on iOS; failed messages vanishMedium
PlatformiOS (React Native)
StepsOn an iPhone, open a support ticket and tap the message box. The keyboard covers the input. If sending fails, the message disappears without any warning.
Root causeAndroid resizes the window for the keyboard, but iOS doesn't, and the screen had no keyboard handling. Send errors were also swallowed.
FixWrapped the chat in KeyboardAvoidingView, made sent messages appear instantly (optimistic update), and added an alert when a send fails.
StatusFixed · retested on iOS and Android
BUG-07Live order map zooms out to show two continentsMedium
PlatformWebsite (React / Next.js)
StepsOpen an active order's tracking map. The map zooms out across the world instead of showing the route.
Root causeA rider device was sending test GPS coordinates thousands of km away, and the map fitted its bounds to include that point.
FixIgnore any rider position more than 100 km from both the store and the delivery address.
StatusFixed · retested live and delivered orders
BUG-08Sign-up form lags while typing on low-end phonesLow
PlatformMobile app (React Native)
StepsType in any sign-up or OTP field on a budget Android device. Input feels delayed.
Root causeComponents read the whole global store, so every keystroke re-rendered all form fields across 10 auth screens.
FixEach component now subscribes only to the values it uses (Zustand useShallow), so typing re-renders just the active field.
StatusFixed · retested all auth screens
